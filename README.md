# worklog 폴더 사용법

## 폴더 구조
- `raw/YYYY-MM-DD.md` — 그날 있었던 업무를 자유 형식 불릿으로 기록. 하루 중 아무 때나
  떠오를 때 이어서 적으면 됨(append). 퇴근 직전 3~5줄로 몰아 써도 무방.
- `.sync-state.json` — 에이전트가 각 파일에서 "어디까지 처리했는지" 줄 번호를 기록해두는
  상태 파일. 사람이 직접 수정할 필요 없음. 삭제하면 전체 재처리됨(중복 생성 위험 있으니 주의).
- `processed/` — 현재 버전(v3)에서는 파일을 옮기지 않고 `.sync-state.json`으로만 관리하므로
  비워둬도 무방. 과거 버전(v2) 방식으로 되돌릴 경우를 대비해 남겨둠.

## 작성 예시
```
- Apeiron 소개 장표 만듦. Bain IM 자료 재구성함. SAF 신사업 오프테이크 검토용.
- 용선료 리서치는 결국 수치 못 구함. 전쟁보험료 변수가 너무 컸음.
```
- 완결된 문장일 필요 없음. 육하원칙을 다 채우지 않아도 됨 — 에이전트가 이 메모를
  아젠다-접근-결과 구조의 보고체 문단으로 재구성함.
- 사실만 적을 것. 여기 없는 내용은 에이전트가 임의로 지어내지 않음(정보가 부족하면
  해당 항목을 비워두거나 사용자에게 되물음).

## 에이전트 동작 (오후 5시 폴링)
1. `raw/` 안의 최근 3일치 파일을 스캔.
2. `.sync-state.json` 기준으로 "새로 추가된 줄"만 골라 처리.
3. 새 줄이 하나도 없으면 → 사용자에게 알림("오늘 업무 알려주세요" 또는 "오늘은 없나요?").
4. 새 줄이 있으면 → 업무 단위로 나눠 Notion "업무일지" DB에 각각 페이지 생성
   (활동/날짜/소속/인사이트/유관 직무/활용능력/5축/소재 매력도/역량 및 키워드/자소서 문항유형
   자동 판단, 페이지 본문은 업무 상세설명·As-Is-To-Be·자소서 요약 50/100/1000자).
5. 처리 완료 후 `.sync-state.json` 갱신.

## 설치 방법
1. 이 `worklog/` 폴더 전체를 Claude Code가 접근하는 실제 GitHub 저장소 루트(또는 원하는
   위치)로 복사.
2. Claude Code 쪽 예약 루틴(오후 5시 폴링)에 v3 로직 프롬프트를 등록.
3. 매일 `raw/YYYY-MM-DD.md`에 메모를 남기는 습관 시작.
